# MCD 60 帧开放词汇二维误差分解记录（2026-08-03）

## 目的

本实验不训练新的 3D Gaussian，也不调整语义 loss。它首先回答开放词汇语义误差发生在 SAM 区域、完整 OpenCLIP 表征还是 PCA128 压缩。只有二维链路通过预注册门槛后，才允许把主要精力投入 2D-to-3D 融合和语义头优化。

## 固定设置

- 帧范围：MCD `ntu_day_02` 的 1800–1859，共 60 帧。
- 训练关键帧：每 5 帧取 offset 4，共 12 帧。
- held-out：排除与训练关键帧共享 LiDAR 标注 scan 的 12 帧，剩余 36 帧。
- 有效 held-out 统计单位：18 个独立 `label_scan_index`，每个 scan 对应 2 张投影图像。
- 2D teacher：SAM1 ViT-H，`points_per_side=32`，OpenCLIP ViT-B/16。
- 压缩：冻结的 512→128 PCA 基底。
- 主评价域：所有置信度不低于 0.35 的稀疏参考像素；缺失预测按 unknown 计错。
- 文本提示、PCA 基底、数据划分和类别集合在 held-out 评价前冻结。

MCD 标签只被评价器读取，没有进入 SAM mask 生成、OpenCLIP 特征、PCA 拟合或 Gaussian 优化。

## 主结果

| 阶段 | Held-out macro-IoU | 相对上一阶段保留率 | 预注册门槛 | 结论 |
|---|---:|---:|---:|---|
| S0 SAM Oracle | 0.3851 | — | ≥0.50 | Gate B 失败 |
| S1 Full OpenCLIP | 0.1368 | 35.5% | ≥70% of S0 | Gate C 失败 |
| S2 PCA128 | 0.0897 | 65.6% | ≥95% of S1 | Gate D 失败 |

按 18 个 LiDAR 标注 scan 进行 2000 次 group bootstrap：

| 量 | Bootstrap mean | 95% CI |
|---|---:|---:|
| S0 macro-IoU | 0.3836 | [0.3644, 0.4036] |
| S1 macro-IoU | 0.1368 | [0.1304, 0.1433] |
| S2 macro-IoU | 0.0898 | [0.0749, 0.1034] |
| S0−S1 | 0.2468 | [0.2264, 0.2673] |
| S1−S2 | 0.0470 | [0.0350, 0.0607] |

两个阶段损失的置信区间都没有跨 0，因此现有 2D 链路中至少存在三个连续瓶颈：SAM 分区上限不足、OpenCLIP 区域识别损失、PCA128 额外损失。最早失败是 S0，所以当前不得先调 3D semantic loss。

## SAM 失败的进一步分解

| 类别 | 参考像素 | SAM 覆盖率 | 覆盖像素上的 oracle 正确率 | 全参考 oracle recall |
|---|---:|---:|---:|---:|
| ground | 106,568 | 92.42% | 95.58% | 88.33% |
| building-structure | 154 | 100.00% | 68.18% | 68.18% |
| vegetation | 109,789 | 94.38% | 96.20% | 90.80% |
| barrier-fence | 1,202 | 96.26% | 60.93% | 58.65% |
| pole-sign | 11,854 | 91.76% | 40.55% | 37.21% |
| vehicle | 8,492 | 76.22% | 62.10% | 47.34% |
| pedestrian | 329 | 99.70% | 3.35% | 3.34% |
| bike | 256 | 100.00% | 0.00% | 0.00% |
| furniture-object | 879 | 87.37% | 13.93% | 12.17% |
| cliff | 0 | N/A | N/A | N/A |

`pedestrian` 和 `bike` 几乎全部落在某个 SAM 区域内，却无法被区域多数票恢复。这不是“总覆盖率太低”，而是小类没有得到足够纯净的独立区域，或参考投影与图像实例并不严格对齐。代码把该项命名为 `covered_but_not_oracle_correct`，避免未经验证就把它全部称为 SAM 合并错误。

## 对抗式审查与已修正问题

1. 初版 macro-IoU 把参考中不存在的 `cliff` 类也纳入平均，只因模型预测了该类就给 IoU 0。这违反预注册规则。现已改为只有参考 support 大于 0 的类进入 macro-IoU，并保留该类 false positive 与 precision 诊断。修正后 S1 从 0.1232 变为 0.1368，S2 从 0.0808 变为 0.0897；结论没有反转。
2. 初版置信区间按连续 3 帧重采样，但同一 LiDAR 标注 scan 被投影到两张相机帧，时间块可能拆开相关样本。现改为按 18 个 `label_scan_index` 成组重采样。
3. 高 SAM pixel coverage 不能证明小物体被正确分割。一个覆盖整幅图的大区域同样能产生高覆盖率，因此新增按类的“未覆盖”和“已覆盖但 oracle 不正确”分解。
4. S0 使用评价标签为区域赋多数类，只是不可部署上限，不能作为方法结果。
5. MCD 参考是稀疏 LiDAR 投影，不是稠密人工 2D mask。小类 support 很低，且图像与标签 scan 的绝对时间差最高可接近 0.05 s；动态目标、标定误差和遮挡变化可能模拟区域合并。需要代表帧可视化和独立人工 2D 小规模核验。
6. 当前 teacher 是单尺度、单张互斥 region-id 图的诊断实现，并非完整 LangSplatV2 多尺度复现。不能把本结果外推成“LangSplatV2 的 SAM1 上限”。
7. 60 帧窗口来自单场景和单时段；Gate 全部通过前不扩展 4558 帧，通过后仍需额外场景验证。

## 下一项单变量实验

训练关键帧基线 `points_per_side=32` 的 SAM Oracle macro-IoU 为 0.3784，参考覆盖率为 92.97%。下一项只把 `points_per_side` 改为 64，并只在相同 12 个训练关键帧上比较：

- 主选择指标：训练帧 SAM Oracle macro-IoU；
- 小类诊断：pedestrian、bike、furniture-object 的覆盖像素 oracle 正确率；
- 反作弊指标：参考覆盖率不得通过大幅拒绝困难像素而虚假提升；
- 决策：训练侧有实质改善才冻结配置并生成完整 60 帧 teacher，held-out 只评价一次；
- 若没有改善：停止增加点采样，转向保留 SAM small/medium/large 多尺度假设，并对 mask 投影与实例边界做人工小样本核验。

由于实验服务器 GPU0、GPU1 在记录时均被其他用户任务占用，`points_per_side=64` 尚未启动；没有抢占、终止或混用他人 GPU 进程。
